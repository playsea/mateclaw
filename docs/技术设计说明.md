# MateClaw 技术设计说明

> **版本**：2.1.0 · **受众**：本仓库维护者与 AI 编程助手  
> **目的**：沉淀架构、设计思路与改码地图，避免每次会话重新通读代码。  
> **配套**：产品向架构见 `mateclaw-server/src/main/resources/docs/zh/architecture.md`；Windows 本地启动见 [DEV_WINDOWS.md](./DEV_WINDOWS.md)。

---

## 1. 一句话定位

MateClaw（太一）是 **企业可部署的 Agent Harness**：Spring Boot 内核 + StateGraph（ReAct / Plan-Execute）运行时，多工作空间隔离、审批闸门、审计、多模型故障转移；**一个 JAR 交付**（前端静态资源打进后端）。

不是「聊天框 + 一次 RAG」，而是工具 / 技能 / MCP / ACP 收敛到统一注册表、每位数字员工独立绑定的完整运行时。

## 3. 技术栈（以根 POM / package.json 为准）

| 层 | 选型 |
|----|------|
| 语言 / 运行时 | Java **21**、虚拟线程（`spring.threads.virtual.enabled=true`） |
| 框架 | Spring Boot **3.5.x**、Spring Security + JWT |
| Agent 图 | Spring AI Alibaba **graph-core**（`StateGraph` / `CompiledGraph`） |
| 模型 | Spring AI + Alibaba DashScope；配置以**管理台模型表**为准，非仅 `application.yml` |
| 持久化 | MyBatis Plus、Flyway；开发默认 **H2 文件库**，生产 Postgres / MySQL / Kingbase profile |

| 前端 | Vue 3、Vite、Pinia、Element Plus、Tailwind 4、vue-router |
| 定时 | `@EnableScheduling` + ShedLock（多实例防重） |

入口类：`vip.mate.MateClawApplication`  
（显式 exclude 了 Spring AI MCP Client 自动配置与 DashScope Agent 自动配置——MCP 生命周期由 `McpClientManager` 接管，模型由管理台驱动。）

## 4. 总体架构

```
┌─────────────┐  ┌──────────────┐  ┌────────────────────────────┐
│ mateclaw-ui │  │ Desktop /    │  │ IM Channels / WebChat      │
│ Vue SPA     │  │ WebChat      │  │ DingTalk Feishu WeCom …    │
└──────┬──────┘  └──────┬───────┘  └─────────────┬──────────────┘
       │ HTTP/SSE        │                        │ Adapter
       └─────────────────┼────────────────────────┘
                         ▼
              ┌──────────────────────┐
              │ ChannelMessageRouter │  ← IM / WebChat 汇聚
              │ ChatController       │  ← 控制台 SSE
              └──────────┬───────────┘
                         ▼
              ┌──────────────────────┐
              │     AgentService     │  执行门面（缓存 per-conversation Agent）
              │  AgentGraphBuilder   │  编译 ReAct / Plan-Execute 图
              └──────────┬───────────┘
                         ▼
              StateGraph 循环（推理 ↔ 工具 ↔ 观察 / 计划 ↔ 步骤）
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
   ToolRegistry    ProviderRouter   Memory / Wiki / Skill
   + ToolGuard     + Failover       + Workspace 隔离
```

**设计原则（代码与 README 一致）：**

1. **同一大脑，多扇门** — 控制台 / 桌面 / WebChat / IM / 插件共用 `AgentService`。
2. **Harness 而非单次调用** — 控制流在 StateGraph，不在 Controller。
3. **工作空间真相在 DB 成员关系** — `X-Workspace-Id` 只是提示；权限以成员角色为准。
4. **能力按员工绑定** — 技能 / MCP / 工具不跨 Agent 泄漏。
5. **Workflow ≠ Agent 图** — 业务流程用 `WorkflowRunner` 步进 DSL；Agent 内部仍走 StateGraph。
6. **危险操作 fail-closed** — ToolGuard 审批、Trigger 去重/限速/未知 pattern 拒绝。

## 6. Agent 运行时（核心）

### 6.1 职责拆分

| 类 | 职责 |
|----|------|
| `AgentService` | CRUD + **运行时门面**：按会话取/建 Agent、流式对话、回放（审批后）、生命周期事件 |
| `AgentGraphBuilder` | **只负责编译**：选模型、绑工具/技能/MCP、组装 ReAct 或 Plan-Execute 图 |
| `StateGraphReActAgent` | ReAct 执行与 `Flux<StreamDelta>` |
| `StateGraphPlanExecuteAgent` | 计划生成 → 步骤执行 → 汇总 |

Agent 类型字段：`react` | `plan_execute`（实体 `AgentEntity`）。

### 6.2 ReAct 图（示意）

```
START → Reasoning
          ├→ Action → Observation →（回 Reasoning / Summarizing / FinalAnswer …）
          ├→ FinalAnswer →（可选 GoalEvaluation）→ END
          ├→ Summarizing → Reasoning
          └→ LimitExceeded → FinalAnswer
```

主要节点：`ReasoningNode`、`ActionNode`、`ObservationNode`、`SummarizingNode`、`LimitExceededNode`、`FinalAnswerNode`、`GoalEvaluationNode`。

### 6.3 Plan-Execute 图（示意）

```
START → PlanGeneration
          ├→ DirectAnswer → END
          └→ StepExecution ⇄ PlanSummary / 有界重计划 →（GoalEvaluation?）→ END
```

### 6.4 聊天主路径（控制台）

```
mateclaw-ui ChatConsole
  → POST /api/v1/chat/stream（Bearer + X-Workspace-Id）
  → ChatController
       · 落库用户消息（ConversationService）
       · ChatStreamTracker 注册 SSE（重连 / 停止 / 队列）
       · 虚拟线程执行 AgentService.chatStructuredStream
            → getOrBuildAgentForConversation
            → StateGraph*.chatStructuredStream → Flux<StreamDelta>
  → SSE：thinking / tool / content / plan / phase …
  → 落库助手消息；触发记忆生命周期
```

IM / WebChat：Adapter → `ChannelMessageRouter` → 同一 `AgentService`。  
审批通过后：`chatWithReplayStream` 续跑。

Team Run：稳定 `runId` 串起任务 DAG / 成员会话 / 交付物；Chat、Agents Live、Teams **读同一投影**。

## 7. 能力扩展面

| 机制 | 形态 | 要点 |
|------|------|------|
| 内置 `@Tool` | JVM 工具 | 经 `ToolRegistry`；敏感调用经 ToolGuard |
| SKILL.md | 包（manifest + prompt + 工具 + LESSONS） | 工作区目录；可进化/快照；安装 Pre-flight |
| MCP | stdio / SSE / HTTP | `McpClientManager` 自管生命周期；**按员工绑定** |
| ACP | Claude Code / Codex 桥 | 包装成技能 + 工具 |
| Plugin JAR | `MateClawPlugin` | 加载顺序：工作区 > 用户全局 > classpath；可注册 tool / LLM / channel / memory / search |

**ToolGuard**：规则 → `NEEDS_APPROVAL` → 审批流 / IM 卡片 → 回放执行。  
**Provider 故障转移**：管理台排序 + `AvailableProviderPool` + `ProviderHealthTracker` 冷却 + `ProviderRouter` 能力感知。

## 8. 工作空间、安全与 API 约定

- **RBAC**：工作空间角色（Owner / Admin / Member / Viewer）+ 全局管理员；注解如 `@RequireWorkspaceRole`、`@RequireGlobalAdmin`。
- **认证**：JWT；PAT 用于脚本/CI；部分 SSO。
- **统一响应**：`R<T> { code, msg, data }`；前端 Axios 在 `mateclaw-ui/src/api/index.ts` 解包。
- **前端 API 前缀**：`/api/v1`；Vite 开发代理到 `http://localhost:18088`（含 `/skill-assets`、WebSocket）。
- **默认端口**：后端 `18088`，前端 Vite `5173`，Docker 对外常见 `18080`。
- **默认账号（开发）**：`admin` / `admin123`（若本地改过密码以实际为准）。

## 10. 数据与配置

- **ORM**：MyBatis Plus（无 JPA）。
- **迁移**：`src/main/resources/db/migration/{h2,mysql,kingbase}/`（大量 V* 脚本）；Postgres profile 走兼容策略。
- **开发库**：`jdbc:h2:file:./data/mateclaw`（相对 `mateclaw-server` 工作目录）。
- **Profile**：`application.yml` 默认 `dev`；另有 `postgres` / `mysql` / `kingbase`。
- **LLM Key**：优先管理台「设置 → 模型」持久化；yml 中 DashScope key 仅为自动配置兜底。
- **日志**：`logback-spring.xml`，控制台 UTF-8；Windows 乱码见 DEV_WINDOWS。

## 11. 本地开发（Windows）速查

```powershell
# 环境（强制 JDK 21，勿用系统 JDK 17）
. E:\project\mateclaw\scripts\dev-env.ps1

# 一键启停（已运行则先杀进程树再启）
.\scripts\dev-start.bat
.\scripts\dev-stop.ps1

# 仅编译后端
mvn clean compile -pl mateclaw-server -am -DskipTests

# 后端启动（PowerShell 中 -D 参数必须加引号）
cd mateclaw-server
mvn spring-boot:run '-Dmaven.test.skip=true'
```

注意：

1. `JAVA_HOME` 需指向内层目录，如 `...\jdk-21_windows-x64_bin\jdk-21.0.11`。
2. `spring-boot:run` 在 **`mateclaw-server` 目录**执行；根目录 `-am` 会误触 parent POM。
3. 编译前若后端占用 `.flattened-pom.xml`，需先停服务。
4. `-DskipTests` 仍会 **编译** 测试；开发启动用 `-Dmaven.test.skip=true`。

## 13. 关键不变量（勿轻易破坏）

1. 渠道入口最终应汇聚到 `AgentService`（或明确记录的旁路）。
2. Agent 能力绑定必须按 `agentId` / conversation 作用域解析。
3. Workspace 授权以 DB 成员为准，不信任客户端随意传的 workspaceId。
4. MCP 不要重新启用被 exclude 的 Spring AI MCP 自动配置，除非整体接管策略重写。
5. Workflow 步进与 Agent StateGraph 保持边界清晰。
6. 流式协议阶段（thinking / tool / answer）与前端 SSE 消费保持一致。
7. 单 JAR 交付：UI build 产物路径勿随意改，以免桌面/Docker 打包断链。
